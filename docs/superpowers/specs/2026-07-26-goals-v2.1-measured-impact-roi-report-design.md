# Goals v2.1: Measured Durations & Exportable ROI Report — Design

**Date:** 2026-07-26
**Status:** Approved (design review with James, 2026-07-26)
**Builds on:** v1 goals spec + v2.0 spec (recurrence/periods used by the report)

## Problem

The proof layer's estimated tier rests on hand-tagged per-run minutes, and the
proof lives only inside the app. v2.1 hardens the numbers (measured AI run
time, user-calibrated estimates) and makes the proof portable — a
board-ready PDF for the person defending the spend.

## Decisions (settled in design review)

1. **Generated PDF download** (user choice over a print-page). New dependency:
   `@react-pdf/renderer` — pure-JS, serverless-safe, no headless browser.
   Charts reuse the pure `chart-math` helpers feeding react-pdf `<Svg>/<Path>`.
2. **Measured run time enters the impact model**: flow runs from
   `finishedAt − startedAt`, agent runs from `AgentExecution.executionTime`.
   It is displayed as measured AI time — it is NOT claimed as time saved.
3. **Estimates become calibratable**: inline editing of a contribution's
   `estimatedMinutesSavedPerRun`, and a platform-wide weekly calibration that
   sets each catalogue seed's effective default to the median of user-edited
   link estimates once ≥ 3 distinct orgs have edited (k-anon floor). Existing
   links never change retroactively.

## Measured durations

- `contributionStats` (`src/lib/goals/impact.ts`) additionally returns
  `measuredRunSeconds: { total: number; avg: number | null }` per contribution:
  flows sum `finishedAt − startedAt` over succeeded runs after link time;
  agents sum `executionTime` (ms → s) over completed runs. Null avg when zero
  runs.
- `ImpactTiers.measured` gains `aiRunSecondsTotal`; the contribution list API
  returns per-link `avgRunSeconds`.
- UI: contribution rows show "avg 42s AI time / run"; the goal impact panel
  adds the comparative line **"42s of AI time vs ~25 min manual estimate per
  run"** (formatter handles s/min/h). Tier labels: AI time is *measured*;
  the manual minutes remain *estimated*.

## Inline estimate editing + calibration

- **API:** `PATCH /api/goals/[id]/contributions` body
  `{ contributionId, estimatedMinutesSavedPerRun (int 1..480) }` — goal
  visibility enforced, updates the link, records
  `UserEvent('goal_estimate_edited', context: { seedKeyIfKnown })`. New
  `USER_EVENT_KINDS` entry: `goal_estimate_edited`.
- To attribute an edit to a seed, `GoalContribution` gains `seedKey String?`,
  set at provision time when the contribution came from a catalogue seed
  (null for manual links to bespoke automations).
- **UI:** the contribution row's minutes value becomes an inline editable
  field (pencil affordance → number input → save on blur/Enter, toast on
  error).
- **Calibration sweep** (`src/lib/goals/calibrate-estimates.ts`, weekly cron
  leg beside the archetype aggregation): for each `seedKey`, collect current
  `estimatedMinutesSavedPerRun` from links whose value differs from the seed's
  shipped default (= user-edited), across ALL orgs via `systemPrisma`
  (justified: global k-anon aggregation, CRON_SECRET-gated). Where ≥ 3
  distinct orgs contributed, upsert into a new global table
  `TemplateEstimateCalibration { seedKey @id, medianMinutes, orgCount,
  updatedAt }` (no orgId — global, like `PlatformArchetype`).
- **Consumption:** provision-time seeding reads
  `calibration?.medianMinutes ?? seed.estimatedMinutesSaved ?? 30`. The
  wizard/panel shows "calibrated from N teams" when a calibration was used
  (`GoalContribution` note derived at read time from the calibration table).

## PDF ROI report

- **Route:** `GET /api/goals/report?months=3|6|12` (default 3),
  `withAuthenticatedApi`, returns `application/pdf` with
  `Content-Disposition: attachment; filename="sublime-roi-report.pdf"`.
  Registered in the smoke guard (asserts status < 500 like any GET).
- **Renderer:** `src/lib/goals/report/` — `report-data.ts` (assembles the
  payload: org impact tiers, per-goal series/evaluation/periods/contributions
  with measured time; all viewer-visibility-filtered) and `report-pdf.tsx`
  (react-pdf document; no app-component imports — react-pdf has its own
  primitives).
- **Content:**
  1. Cover: org name, window, generated date, the three impact tiers as
     labeled figures (measured / estimated / correlated wording printed
     verbatim — the honesty rule survives the export).
  2. Per active or recently-settled goal (cap 12): trendline + pace line
     (chart-math scaled into `<Svg><Path>`), current vs target, risk, period
     history chips, contributions table (name, origin, runs, avg AI time,
     est. minutes/run).
  3. Footer on every page: "Estimates are labeled; correlations are not
     causation." — the defensibility line.
- **UI:** "Export ROI report" `Button` (Download icon) beside the impact strip
  on `/goals`, with a months `Select` (3/6/12) in a small popover; triggers a
  plain `window.location` download.

## Error handling

- Report route with zero goals returns a valid one-page PDF stating "No goals
  tracked yet" (never a 500).
- Calibration sweep and duration joins are best-effort; a failure logs and
  leaves prior calibrations in place.
- PATCH estimate validates range and visibility; concurrent edits last-write-
  win (single integer field).

## Testing

- Unit: duration aggregation math (mixed flow/agent, zero-run null avg),
  median calibration (k-floor, ties, ignores unedited links), report data
  assembly (visibility filtering, cap 12, settled-goal inclusion window).
- Route smoke: `GET /api/goals/report` registered; asserts 200 and
  `application/pdf` content type in the goals e2e.
- e2e: edit an estimate via PATCH → calibration sweep with 3 seeded orgs →
  new provision uses the median; report route streams non-empty PDF bytes.

## Out of scope (v2.1)

- Scheduled/emailed reports (manual export only).
- Per-goal report export (org-level document only).
- Measuring human time saved directly (the estimate stays an estimate —
  calibrated, labeled, never laundered into "measured").
