# Goals v2.2: Postgres Metric Connector & Peer Benchmarks — Design

**Date:** 2026-07-26
**Status:** Approved (design review with James, 2026-07-26)
**Builds on:** v1 goals spec (MetricSource registry), v2.0 spec (GoalPeriod
feeds benchmark outcomes)

## Problem

Custom KPIs mostly live in databases, not SaaS APIs — one read-only SQL
connector covers essentially all of them. And every org tracks its goals
alone: the platform knows how goals of each kind go across orgs but shares
none of it. v2.2 adds the universal intake and the k-anon comparative layer.

## Decisions (settled in design review)

1. **Postgres first** (over Snowflake/BigQuery). New dependency: `pg`.
2. Connection string lives in the **credential vault** (secret field of an
   existing credential type; `connectionRef: 'credential:<id>'`).
3. **Read-only is enforced in three independent layers** (statement shape,
   session mode, timeout) — a write attempt dies before it matters.
4. Benchmarks are **global counts only, surfaced at ≥ 5 orgs**, exactly the
   `PlatformArchetype` k-anon discipline. Never an org name, never a value.

## Postgres metric source

`src/lib/metrics/sources/postgres.ts`, registered as `source: 'postgres'`,
metric key `postgres.query`, `config: { query: string }`.

**Fetch path (hardened layers — updated to match implementation):**

1. Resolve credential (vault scope), decrypt → connection string.
2. **Layer 0 — the string never reaches the driver:** `buildClientConfig`
   parses the URL and constructs explicit `{ host, port, user, password,
   database }` fields, discarding every query param (`pg` merges string
   params OVER explicit config, so a hostile credential could otherwise
   disable the read-only session, zero the timeout, and strip TLS in one
   URL). `sslmode=disable` is rejected by name.
3. **Layer 1 — statement shape:** `validateReadOnlyQuery` — `/^(select|with)\b/i`,
   no `;`, non-empty, ≤ 10_000 chars, PLUS a word-boundary denylist
   (insert/update/delete/DDL/set/copy/nextval/setval/advisory locks/dblink/
   pg_read_file…) so data-modifying CTEs and SELECT-shaped side effects fail
   closed.
4. **Layer 2 — server-enforced, in-band:** the query runs inside
   `BEGIN TRANSACTION READ ONLY` with `SET LOCAL statement_timeout = '10s'` —
   immune to poolers dropping startup packets. `connectionTimeoutMillis` and
   `statement_timeout` are also set on the client config.
5. Execute; require ≥ 1 row; row 0, column 0; numeric coercion via the Sheets
   `parseSheetNumber` rules. `client.end()` in `finally`.
6. Errors are messages only — connection string, username, and password are
   redacted before anything is persisted or displayed.

**Wizard:** source card "Postgres / SQL" (Database icon) listing vault
credentials; `config.query` as a `Textarea` with monospace font and helper
copy ("single SELECT returning one numeric value"); the existing preview step
validates end-to-end before the goal can exist.

**TLS:** certificate verification is NEVER disabled, and verified TLS is the
DEFAULT for every non-loopback host — there is no opt-out. For servers signed
by a private CA, the credential accepts an optional `caCert` (PEM) passed as
`ssl: { ca }`; a verification failure surfaces in the wizard preview with a
hint to supply the CA — the fix is trust material, never
`rejectUnauthorized: false`. Loopback hosts (localhost/127.0.0.1/::1) connect
without TLS — the bytes never leave the machine, and this keeps local/CI
verification working. Supabase/RDS use publicly-verifiable chains and work
with default verification.

## Peer benchmarks

### `GoalBenchmark` (new GLOBAL model — no organizationId, like `PlatformArchetype`)

| Field | Type | Notes |
| --- | --- | --- |
| `kind` | String `@id` | goal kind ('arr', 'mrr', 'quota', …) |
| `orgCount` | Int | distinct orgs with ≥ 1 settled outcome of this kind |
| `settledCount` | Int | settled goals + settled periods, all orgs |
| `achievedCount` | Int | subset with outcome/status achieved |
| `topSeedKeys` | Json | up to 3 `{ seedKey, name, deploys }` from goal-tagged template adoption |
| `updatedAt` | Timestamptz | |

### Aggregation

`src/lib/goals/aggregate-benchmarks.ts` — weekly cron leg (same window family
as archetype aggregation). Via `systemPrisma` (justified: global k-anon
aggregation, CRON_SECRET-gated):

- Outcomes = `Goal` rows with status `achieved`/`missed` (one-shot) UNION
  `GoalPeriod` rows (recurring), grouped by kind; `orgCount` via distinct
  organizationId. Reads are EXACT grouped aggregates (Prisma `groupBy` for
  goals, a raw joined `GROUP BY` for periods) — never capped row samples,
  which would silently deflate `orgCount` toward the k-floor as volume grows.
- `topSeedKeys` from the adoption scores of seeds tagged with that goal kind.
- Upsert per kind; kinds falling below activity keep their last row (staleness
  visible via `updatedAt`).

### Surfacing (only when `orgCount >= 5`)

- **API:** benchmark for the goal's kind joins the `GET /api/goals/[id]`
  response (`benchmark: { orgCount, achievedRate, topSeeds } | null` — rate
  rounded to whole percent; null below the k-floor or when no row).
- **Goal detail card** "How teams like yours do": *"62% of 14 orgs tracking
  MRR targets hit their last period. Most-adopted play: Pipeline Reviver."*
  Muted styling; explicitly labeled "anonymous, cross-workspace counts".
- **Emission evidence:** `emitGoalRecommendation` appends one line when a
  surfaced benchmark exists: *"Across N teams tracking this kind of goal, X%
  hit their last target."*

## Error handling

- Postgres fetch failures follow the v1 contract: message on
  `GoalMetric.lastError`, goal degrades to `no_data`, tick never fails.
- Benchmark aggregation failure logs and keeps prior rows; the detail card
  and evidence simply omit when null.
- The benchmark API join is read-only and cheap (single PK lookup by kind).

## Testing

- Unit: `validateReadOnlyQuery` (accepts select/with; rejects semicolons,
  updates, deletes, DDL, empty, over-length), numeric coercion of row values,
  benchmark math (achievedRate, k-floor null, topSeedKeys ranking).
- Adapter test with an injected fake `pg` client asserting session options
  (`default_transaction_read_only`, `statement_timeout`) and single-statement
  execution.
- e2e: seed 5 orgs with settled goals → aggregation → benchmark surfaces on a
  6th org's goal detail; 4 orgs → null (k-floor). Postgres source e2e against
  the throwaway QA database itself (a real `SELECT 42` through the vault).
- Smoke guard: no new GETs beyond existing registered routes (benchmark rides
  the `[id]` response).

## Out of scope (v2.2)

- Snowflake / BigQuery connectors (registry is the extension point).
- Benchmark segmentation by org size/industry (needs more data than k=5).
- Cross-org pace/value distributions (counts and rates only — values never
  leave their org).
