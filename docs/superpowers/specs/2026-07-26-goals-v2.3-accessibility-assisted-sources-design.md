# Goals v2.3: Auto Units, Lead Gen, Goal Templates, Assisted Sources — Design

**Date:** 2026-07-26
**Status:** Approved (design review with James, 2026-07-26)
**Builds on:** goals v1 + v2.0–v2.2 (all on `feat/goals`)

## Problem

The wizard makes users pick a unit their goal kind already implies, offers a
kind (CARR) nobody asked for while missing Lead Gen, starts everyone from a
blank form, and reads as if goals require one of four SaaS integrations.
Users whose numbers live in Slack messages, report emails, a dashboard URL,
or a CSV export should be able to track goals TODAY — and be nudged toward a
stronger source of truth, never blocked by the lack of one.

## Decisions (settled in design review)

1. **Kind dictates unit.** `GOAL_KIND_UNITS`: arr/mrr/revenue/quota/savings →
   `usd`, `lead_gen` → `count`, `custom_kpi` → user-selected (only kind that
   renders a unit picker). The server derives the unit from the kind on
   create; a client-sent unit is honored only for `custom_kpi`.
2. **Kind roster:** `'arr' | 'mrr' | 'revenue' | 'quota' | 'savings' |
   'lead_gen' | 'custom_kpi'` — CARR removed, Lead Gen added (increase,
   count). String column, no migration; catalogue seeds retagged so
   `lead_gen` has recommendation coverage.
3. **Goal templates: 20, on `/goals`.** Static catalogue
   (`src/lib/goals/goal-templates.ts`): per served department (sales,
   marketing, engineering, finance, csm) 2 org + 2 personal templates —
   `{ key, department, scope, name, description, kind, direction,
   recurrence }`. A "Start from a template" section on the goals page with
   department filter chips; selecting routes to `/goals/new?template=<key>`
   which prefills name/kind/recurrence/scope. Target value and source remain
   the user's.
4. **Source step reframed.** Two groups, manual first:
   - "Start tracking now": manual, Slack (assisted), Gmail (assisted), URL,
     CSV import — all usable without new SaaS connections.
   - "Stronger sources of truth": Stripe, HubSpot, Salesforce, Sheets,
     Postgres with entice copy ("Connect for exact, automatic tracking");
     sort-never-hide unchanged.
   Goals on manual/assisted/url sources show a quiet upgrade nudge on the
   detail page.
5. **AI-assisted sources are labeled, gated, and cheap.** Extraction runs on
   `DEFAULT_SUMMARY_MODEL` once per refresh interval (daily default), only
   for goals that opted in. Low-confidence extraction FAILS the sync (lands
   on `lastError`) — a fabricated datapoint is worse than a missed one.
   Assisted readings persist with datapoint origin `'assisted'` and wear an
   "AI-read" badge in the UI. The measured/estimated/correlated discipline
   extends to ingestion: exact and assisted readings are never visually
   identical.

## New metric sources (`src/lib/metrics/sources/`)

### `url.ts` — deterministic (`source: 'url'`, key `url.value`)

`config: { url: string; jsonPath?: string }`. Fetch with 10s timeout, 1 MB
response cap, `Accept: application/json, text/*`. JSON body → follow the
dot-path (`data.mrr.current`) when given, else the first numeric leaf found
by breadth-first walk; text body → first parseable number (Sheets coercion
rules). **SSRF guard (`assertSafeUrl`, pure + tested):** http/https only;
reject credentials-in-URL; reject hostnames that are loopback, RFC-1918,
link-local (169.254.0.0/16 — cloud metadata), `.internal`/`.local`, IPv6
loopback/ULA, and bare `localhost` — the worker shares a network with Redis.
Redirects are followed at most 3 times and each hop re-validated.

### `slack-assisted.ts` (`source: 'slack_assisted'`, key `assisted.value`)

`config: { channel: string; metricHint?: string }`. Reads recent channel
messages through the existing built-in Slack read integration (global-env
single-tenant limitation carries over; source is offered only when
`slackConfigured()`). Extraction prompt (structured output, temperature-free):
"latest reported value of <goal name / metricHint>" → `{ found: boolean,
value: number, confidence: 'high' | 'medium' | 'low', evidence: string }`.
`found: false` or `confidence: 'low'` → throw ("No confident reading in
#channel this sync") → `lastError`, no datapoint. Model:
`DEFAULT_SUMMARY_MODEL` via `generateStructured({ model })`.

### `gmail-assisted.ts` (`source: 'gmail_assisted'`, key `assisted.value`)

`config: { query: string; metricHint?: string }`, `connectionRef:
'google:<googleOAuthConnectionId>'` (service `google-mail`). Lists the top 5
matches for the query via the native Google proxy, pulls snippets/bodies
(text stripped, 10k char cap), same extraction contract as Slack.

### CSV import — not a source

`POST /api/goals/[id]/datapoints/import` with a text body (`text/csv`):
`date,value` rows (header optional), max 1000 rows, each upserted on the
day bucket with origin `'backfill'`, then one re-evaluation. Malformed rows
are reported by line number (`{ imported, skipped: [{ line, reason }] }`),
valid rows still land. UI: "Import CSV" button beside "Record value" on the
goal detail page; a wizard "CSV import" card creates the goal as `manual`
and deep-links to the detail page with the import dialog open.

## Datapoint origins

`'sync' | 'manual' | 'backfill' | 'assisted'` (comment update — String
column, no migration). The datapoints table badges `assisted` distinctly
("AI-read"); assisted datapoints chart identically (the caveat lives in the
table + upgrade nudge, not in a diverging line style).

## UI

- Wizard step 1: unit picker renders ONLY for `custom_kpi`; kinds list
  updated (Lead Gen replaces CARR; default recurrence for lead_gen:
  monthly).
- Wizard step 2: two labeled groups per Decision 4; assisted cards carry an
  "AI-read · labeled on every datapoint" note; Slack/Gmail cards show their
  config inputs (channel / search query + optional metric hint) inline when
  selected; URL card shows url + optional JSON path.
- `/goals`: "Start from a template" section (above the goal grid when goals
  exist, below the empty state's CTA otherwise) — department chips filter 20
  compact cards (name, description, org/personal badge, kind label). Click →
  prefilled wizard.
- Goal detail: upgrade nudge (muted, dismiss-free) when
  `metric.source ∈ {manual, slack_assisted, gmail_assisted, url}`:
  "Connect a source of truth (Stripe, CRM, SQL) for exact automatic
  tracking." links to `/goals/<id>`'s edit → step-2 equivalent (v2.3 keeps
  it a link to /integrations).

## API

- `POST /api/goals`: kind enum updated; unit derived server-side
  (`custom_kpi` honors client unit); metric source enum gains
  `url | slack_assisted | gmail_assisted`; per-source config validation
  (url: valid + SSRF-safe at create time; slack: non-empty channel; gmail:
  non-empty query + google-mail connectionRef).
- `GET /api/goals/metrics/sources`: returns the two groups with availability
  (slack_assisted requires `slackConfigured()`; gmail_assisted lists
  google-mail connections; url/manual always available).
- `POST /api/goals/[id]/datapoints/import` (new, registered in the smoke
  guard's non-GET exemption — it is a POST; no guard entry needed).
- Preview route supports the three new sources (assisted preview runs one
  real extraction so the wizard's verify step stays honest).

## Error handling

- URL fetch/parse failures, SSRF rejections, and low-confidence extractions
  all land on `GoalMetric.lastError` with actionable copy; goal degrades to
  `no_data` per the v1 contract.
- Assisted extraction never fabricates: no number → error, never 0.
- CSV import is transactional per row batch; a malformed line never aborts
  the valid remainder.

## Testing

- Unit: `GOAL_KIND_UNITS` derivation (server-side enforcement), template
  catalogue invariants (20 entries, 4 per department, 2 org + 2 personal,
  kinds valid), `assertSafeUrl` matrix (private ranges, metadata IP,
  localhost, credentials, redirect hop), URL JSON-path walker, CSV parser
  (header/no-header, bad lines, cap), extraction-response validation
  (found:false and low confidence both throw).
- Adapter tests with injected fetch/proxy/generate fakes for url + both
  assisted sources.
- e2e: goal created from a template prefill; CSV import → datapoints +
  re-evaluation; smoke re-pass.

## Out of scope (v2.3)

- XLSX parsing (CSV only), AI extraction for the URL source, auto-detecting
  the right Slack channel, per-org Slack credentials (existing single-tenant
  limitation), assisted-source confidence tuning UI.
